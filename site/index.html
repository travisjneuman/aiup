How it works

Fresh input, paired activation, no stale-cache shortcut.

Public runs deliberately begin online. The launcher treats the runtime and catalog as one versioned pair and stops when it cannot prove that pair is complete.

  1. 01

    Install the launcher

    The installer validates its download and places the small launcher in ~/.local/bin. There is no packaged installer or tagged 1.0 release yet.

  2. 02

    Refresh both files on every public run

    The launcher fetches the current runtime and matching catalog manifest from GitHub. A normal public invocation does not use an offline stale-cache fallback.

  3. 03

    Validate and activate atomically

    aiup checks structure and matching versions, stages a complete pair, then switches a single current-generation pointer under a bounded activation lock.

  4. 04

    Keep bounded recovery evidence

    The previous complete generation is retained alongside the current one. It is recovery evidence—not an executable offline fallback.

  5. 05

    Scan locally, then show valid actions

    aiup reads local state, builds the picker, and exposes only actions supported by each reviewed lifecycle contract. Invalid or partial refreshes fail closed.

Safety and privacy

Local inventory stays local. Network actions stay explicit.

aiup has no account, telemetry, analytics, cookies, or inventory upload. It still uses the network where a public launcher and software manager must.

Local scan

PATH entries, app bundles, Homebrew inventory, global npm packages, and uv tools are read on the Mac and stored only in local aiup state.

Bounded network lanes

Each public run contacts GitHub for the runtime pair. Selected actions may then contact GitHub, Homebrew, npm, uv, or the applicable vendor.

Fail closed

A failed, empty, invalid, partial, mismatched, locked, or unactivatable refresh stops. The previous generation is retained but not run offline.

Confirmation where it matters

Explicit uninstall, missing-tap trust, and on-disk app adoption require confirmation. Detected-only items remain read-only.

No direct sudo

aiup does not invoke sudo itself. Homebrew’s official bootstrap or another upstream installer may request administrator authentication.

Honest Homebrew boundary

aiup does not pass --zap or directly delete ~/Library during app adoption. Homebrew and vendor-specific behavior can still vary.

Requirements and installation

Start with a supported Mac and three bootstrap commands.

aiup currently supports macOS 14 Sonoma or newer on Apple Silicon or 64-bit Intel. Linux and Windows are not implemented.

FAQ

Before you run it.

What is aiup?

aiup is a local-first macOS terminal application for scanning, updating, installing, removing, and browsing a reviewed catalog of AI and developer tools.

Which macOS versions are supported?

The current public baseline is macOS 14 Sonoma or newer on Apple Silicon or 64-bit Intel. Individual catalog tools may have stricter requirements.

Does aiup upload my installed-app inventory?

No. Inventory stays on your Mac. Launcher refreshes and selected maintenance actions still make bounded network requests that do not include your local inventory.

Does aiup work offline?

Not for normal public use. Each invocation must refresh and validate the runtime plus catalog from GitHub. The previous generation is retained as recovery evidence, not used as an offline fallback. Contributors can explicitly run a local checkout.

Does it remove application data or settings?

aiup does not promise universal settings preservation. During Homebrew adoption it does not pass --zap or directly delete ~/Library, but Homebrew and vendor-specific installers can behave differently.

Why is fzf required?

fzf provides the searchable, keyboard-driven full-screen catalog. aiup treats it as required infrastructure and installs or updates it through Homebrew.

What does detected-only mean?

aiup found the software locally but does not have a reviewed lifecycle contract for it. The item remains read-only until that contract exists.

Is Linux or Windows supported?

No. Linux and Windows are not implemented. The current product and catalog support macOS only.

Where can I review the source and catalog?

The source repository, generated catalog, status, and MIT license are public on GitHub.
